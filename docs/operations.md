# Эксплуатация

## Настройки

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | `sqlite:///data/hydroflow.db` | SQLite-файл или PostgreSQL URL |
| `PUBLIC_ORIGIN` | HTTP + заголовок Host | Ожидаемый Origin изменяющих запросов |
| `COOKIE_SECURE` | `0` | `1` добавляет Secure к сессионной cookie |
| `HYDROFLOW_ADMIN_PASSWORD` | нет | Начальный пароль для автоматизированной инициализации; в интерактивном режиме используйте запрос пароля |

Программа не читает `.env` самостоятельно; Compose использует его для подстановки. Для запуска без Docker задавайте окружение средствами оболочки. Сервер слушает `127.0.0.1:8000`; `--host` и `--port` меняют адрес. Для доступа по сети используйте `--host 0.0.0.0` только в контролируемой сети с настроенным межсетевым экраном.

## Доступ по HTTPS

Разместите перед приложением обратный прокси с TLS. Установите `PUBLIC_ORIGIN=https://ваш-домен` и `COOKIE_SECURE=1`. Прокси должен сохранять Host, ограничивать размер тела примерно 8 МБ, число соединений и частоту запросов. В конфигурации Compose порт приложения доступен только через loopback хоста; порт PostgreSQL наружу не публикуется.

Waitress обслуживает WSGI; перед ним нужен настроенный TLS-шлюз. Перед использованием с реальными данными проверьте разграничение прав на реальных сценариях и проведите нагрузочные испытания. Проверка соответствия 152-ФЗ, применение сертифицированной криптографии и аудит корпоративной инфраструктуры в разработку не входили.

## Реализованная защита

Пароли хешируются PBKDF2-HMAC-SHA256 с индивидуальной солью, 600 000 итераций. В базе хранится хеш сессионного токена; cookie имеет HttpOnly, SameSite=Strict и срок 12 часов. CSRF-токен требуется для записывающих запросов. Есть проверка Origin, ограничение 15 неудачных или выполняющихся попыток входа с одного IP за 15 минут в процессе сервера, контроль ролей и участия в проекте. Блокировка пользователя и смена пароля отзывают сессии.

SQL-запросы параметризованы. Динамические имена таблиц выбираются только из фиксированного списка сервера. Текст интерфейса экранируется, действует CSP без внешних скриптов. Документы скачиваются как бинарные вложения. Вложения не сканируются антивирусом; для корпоративной установки добавьте такой контроль на отдельном этапе приёма файлов.

Журнал фиксирует операции с сущностями, назначениями и членством, но не является защищённым от действий администратора БД аудитом. Секреты и пароли в журнал не записываются.

## Резервные копии SQLite

```console
python -m hydroflow backup backups/hydroflow-2026-10-26.db
```

Команда использует SQLite Backup API, поэтому копия согласована и при включённом WAL. Имя назначения должно быть новым. Для восстановления остановите сервер, сохраните текущий файл в отдельное место и замените `data/hydroflow.db` копией. При остановленном процессе уберите старые `hydroflow.db-wal` и `hydroflow.db-shm`, если они остались. Перед возобновлением работы проверьте вход, проекты и скачивание вложений.

Исходная база открывается только для чтения и должна существовать: опечатка в пути больше не создаёт пустую базу и ложную успешную копию. Файл назначения создаётся эксклюзивно, существующая копия не перезаписывается. В Docker каталог `/app/data` принадлежит непривилегированному пользователю приложения; для сохранения SQLite между контейнерами подключайте отдельный том. Compose по умолчанию использует PostgreSQL.

## Резервные копии PostgreSQL

```console
pg_dump --format=custom --file=hydroflow.backup --dbname=postgresql://hydroflow@localhost/hydroflow
pg_restore --dbname=postgresql://hydroflow@localhost/hydroflow_restored hydroflow.backup
```

Передайте пароль через запрос утилиты или защищённый `.pgpass`. Для Compose запускайте утилиты внутри контейнера `db` либо через отдельный клиент с доступом к его сети. Восстанавливайте сначала в новую пустую БД, проверьте данные и только затем переключите приложение. Пользователи, документы, история и вложения включены в дамп.

Копии содержат корпоративные данные и парольные хеши: храните их отдельно от Git и ограничивайте доступ. Автоматическое расписание копирования не настроено; выберите его по допустимой потере данных и регулярно проверяйте восстановление.


## Обновление до Flask/v2

Установите `pip install -r requirements.txt` даже для SQLite; затем `python -m hydroflow init` применит v2 без удаления данных. Начальный пароль повторный init не заменяет. Создайте резервную копию до обновления. `TRUSTED_HOSTS` — список разрешённых host через запятую; для локального Compose по умолчанию localhost,127.0.0.1. При внешнем домене добавьте его, сохранив loopback для healthcheck. Чужие Host отклоняются Flask.

Проверки restore, demo и миграции описаны в testing.md. Бесплатный хостинг и PostgreSQL bootstrap — в [deployment.md](deployment.md). Старый `static/index.html` удалён; HTML выдаётся из `templates/app.html` разрешёнными маршрутами.

## Администратор

Откройте `/admin/users`: создавайте пользователей, меняйте системные роли, блокируйте/разблокируйте. Собственную роль/активность менять нельзя. Изменение роли или активности отзывает сессии пользователя. Последний активный ADMIN защищён, включая параллельные действия. Проектные роли остаются отдельными настройками состава команды.

В `/admin/feedback` откройте обращение, задайте ответ и статус. При конфликте версии откройте актуальную запись и сравните ответ. Содержание обращений доступно автору и ADMIN; оно не записывается в audit detail. Лимит 5 новых обращений/час на автора, ключ повторной отправки сохраняет одну запись. Удаление/архивация обращений и политика сроков хранения пока не реализованы; данные учебной установки контролирует владелец.
