# Комплект для проверки

В репозитории: исходники, точные Python-зависимости, Docker/Compose/CI/Render, тесты, README Windows/macOS, API/архитектура/схема/миграции, руководства, тест-план/кейсы/чек-лист/дефекты, фактические результаты, матрица, отчёты объёма и Git, 15 самостоятельных макетов.

Архив исходников создаётся из проверенного Git HEAD:

```sh
git archive --format=zip --prefix=hydroflow/ --output=hydroflow-source.zip HEAD
```

Архив не содержит .git, venv, node_modules, секреты .env, базы/вложения, пароли реальной установки, временные файлы и журналы. .env.example содержит только пустой пароль и локальные адреса; фиксированные пароли в CI/тестах относятся исключительно к одноразовым тестовым данным. Генерируемые учебные пароли в исходный ZIP не включаются.

В локальном каталоге выдачи `outputs/` отдельно находятся `hydroflow-source.zip`, `verification/` (логи и снимки фактических проверок), `demo/hydroflow-demo.db` и `demo/DEMO-ACCESS.txt`. Последние два файла — одна синтетическая установка со случайными паролями всех шести ролей, не конфигурация хостинга и не рабочая БД. Для запуска этой копии укажите абсолютный DATABASE_URL на demo/hydroflow-demo.db и выполните serve из распакованного проекта. БД не подменяет воспроизводимый генератор `scripts/create_demo.py` в исходниках.

Макеты открываются с `docs/mockups/index.html`; они не требуют Python или сервера. Архитектурная схема — docs/data-model.md. Для Git-истории скрипту требуется настоящий клон, а не source ZIP без .git. Сохранённый снимок отчёта доступен в docs/git-history.md; он честно отмечает SHA подсчёта.

После распаковки установите зависимости по README; тесты всегда работают на новых временных SQLite БД. Контрольная сумма архива и итоговый SHA записаны отдельно в outputs/RELEASE.txt, чтобы не создавать самоссылочную контрольную сумму внутри архива.
