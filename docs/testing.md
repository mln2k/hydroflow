# Результаты проверок

Дата: 26 октября 2026 года.

## Выполнено в среде разработки

- `python -m unittest discover -s tests -v`: **25 тестов успешно**, SQLite, Python стандартной библиотеки.
- `python -m compileall -q hydroflow`: синтаксических ошибок Python не обнаружено.
- `node --check static/app.js`: синтаксических ошибок JavaScript не обнаружено.
- Инициализация SQLite, создание администратора и учебного проекта командой `demo`, запуск HTTP-сервера выполнены.
- Команда `backup` проверена на отдельной временной базе: копия открывается, число задач совпадает, `PRAGMA integrity_check` возвращает `ok`.

Тесты проверяют бизнес-правила через реальные транзакции и HTTP-запросы к серверу. Они не доказывают отсутствие всех уязвимостей и не заменяют пользовательскую приёмку.

## Подготовлено, но не выполнено

- PostgreSQL: в среде разработки нет сервера PostgreSQL и драйвера psycopg. Подключение, адаптация схемы и запросов реализованы; отдельное задание CI запускает тот же набор на PostgreSQL 16. До выполнения этого задания совместимость с PostgreSQL считается непроверенной.
- Chromium: сценарий `tests/browser_smoke.cjs` подготовлен, но запуск остановился до открытия приложения, поскольку в среде нет исполняемого файла браузера. Прохождение браузерного сценария, визуальная проверка и отсутствие ошибок в мобильной вёрстке пока не подтверждены. Workflow устанавливает Chromium в GitHub Actions и выполняет сценарий.
- Docker Compose: конфигурация подготовлена, сборка и развёртывание в этой среде не выполнялись, Docker отсутствует.
- Удалённые GitHub Actions: статус можно утверждать только после публикации и завершения заданий.
- Нагрузочные испытания, измерение экономического эффекта и проверка на производственных данных не выполнялись.

## Ручная приёмка

1. Создать пользователей PM, ANALYST, DEV, QA, VIEWER и отдельный проект.
2. Добавить участников; проверить, что посторонний пользователь не видит проект.
3. Создать требование, согласовать его, изменить аналитиком и убедиться в возврате в черновик.
4. Открыть одну редакцию в двух окнах; сохранить в одном и убедиться в конфликте 409 при сохранении во втором.
5. Назначить задачу разработчику; проверить, что другой исполнитель не меняет её статус.
6. Загрузить файл, создать новую версию и скачать старый файл без изменений байтов.
7. Проверить отчёт, CSV, JSON и печать.
8. Заблокировать участника; убедиться, что его открытая сессия больше не работает.
9. Сделать резервную копию и восстановить её в отдельной установке.
