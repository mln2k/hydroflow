### Что проверяют новые тесты

- HTTP: положительные и отрицательные действия всех ролей, PM проекта с системной ролью DEV, подбор команды, запрет перевода назначенного исполнителя в VIEWER, удаление заблокированного участника после снятия назначений.
- Изоляция: чужой проект, отдельный объект, документ с вложением и история версий, отчёты CSV/JSON, подмена ID требования/этапа.
- Требования: согласование PM, возврат в черновик аналитиком, повторное согласование, строгий целочисленный version. DEV/QA: назначенная и неназначенная задача, запрет изменения реквизитов, фактические даты.
- Конкурентные транзакции: один победитель при правке одной версии требования/документа; одна история и одна запись журнала; дублирующийся код; назначение против удаления участника; комментарий против удаления задачи. Ошибка после записи снимка откатывает строку, историю и журнал.
- Сессии: блокировка, смена пароля с отзывом нескольких сессий, старый пароль, CSRF с не-ASCII символом, лимит попыток входа. Ошибочные JSON, Unicode, глубина и слишком большие ID не дают 500.
- Браузер: роли и доступность действий, согласование/изменение, две формы с конфликтом и сохранением введённого текста, побайтовая проверка старого вложения, XSS-строки в списках/диалогах/истории/комментариях без появления HTML-элементов, ошибка сети и повтор комментария, двойной submit, фокус поля диалога, истёкшая сессия, повтор начальной загрузки, все вкладки на 390 px.

### Запуск PostgreSQL и безопасность подготовки

`TEST_DATABASE_URL` должен указывать на отдельную одноразовую PostgreSQL БД. Нужны psycopg из requirements.txt и права CREATE SCHEMA. Каждый тест создаёт уникальную схему `hydroflow_test_<uuid>` и удаляет только её через безопасно экранированный идентификатор. Массовое DELETE из существующих таблиц удалено. Внешние SQLite URL отклоняются; для SQLite всегда создаются временные файлы. CLI-тесты используют SQLite независимо от TEST_DATABASE_URL.

### CI и ограничения

В workflow добавлены новый браузерный аудит, синтаксические проверки и сборка/запуск Docker Compose с отдельными CI-данными. Actions закреплены по SHA веток v6; совместимость Node 24 и требования к runner сверены с официальными [checkout](https://github.com/actions/checkout/tree/v6), [setup-python](https://github.com/actions/setup-python/tree/v6), [setup-node](https://github.com/actions/setup-node/tree/v6). Используются GitHub-hosted ubuntu-latest и contents: read. Версии Python приложения 3.11–3.13 и Node приложения 22 сохранены. Диапазон psycopg 3 оставлен без необоснованной смены основной версии.

Локально PostgreSQL и Docker отсутствуют. Они проверены в [GitHub Actions #5](https://github.com/mln2k/hydroflow/actions/runs/40499708234), коммит `055421f2c1e85153c0abe7ca60e534f799d54675`: все шесть заданий завершились успешно.
