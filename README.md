# HydroFlow

Веб-приложение для управления разработкой ПО, предназначенного для поддержки гидротехнических строительных работ. Границы и функциональные правила описаны в docs/requirements.md; текущая доработка следует тексту задания владельца.

Приложение управляет процессом разработки. Инженерные расчёты сооружений, управление строительной площадкой, бухгалтерия и интеграции с BIM/ERP в предметную область не входят.

## Возможности

- Проекты: описание, заказчик, сроки, статусы, команда и роли участников.
- Требования: код в пределах проекта, приоритет, согласование, история редакций, причина изменения, защита от перезаписи устаревшей версии.
- Задачи: доска и таблица, сроки, тип, приоритет, несколько исполнителей, связи с требованиями и этапами, фактические даты начала и окончания.
- Этапы: плановые даты, статусы и количество выполненных задач.
- Документы: текст, файлы до 5 МиБ, версии содержимого и вложений.
- Комментарии к требованиям, задачам и документам.
- Отчёты: завершённость, просрочки, распределение задач, связи изменённых требований с завершёнными задачами, CSV и JSON, печать.
- Доступ: шесть ролей, изоляция проектов, управление учётными записями, смена пароля, блокировка с отзывом сессий.
- Журнал действий, миграции схемы v1/v2 и команда резервного копирования SQLite.
- 15 отдельных URL, хлебные крошки, мобильное меню, личный кабинет, обращения и административные ответы.

## Быстрый запуск на Windows, Linux или macOS

Нужен Python **3.11 или новее**. Backend работает на Flask 3.1.3 и Waitress 3.0.2; зависимости нужны и для SQLite. Выполняйте команды из каталога с этим README:

Windows PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m hydroflow init
.\.venv\Scripts\python.exe -m hydroflow demo
.\.venv\Scripts\python.exe -m hydroflow serve
```

macOS / Linux:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m hydroflow init
python -m hydroflow demo
python -m hydroflow serve
```

Команда `init` предложит задать пароль администратора: от 12 до 128 символов. Адрес по умолчанию — `admin@example.local`; другой адрес можно указать через `--email`. Команда `demo` необязательна: она создаёт учебный проект и вымышленные учётные записи, печатает их случайные пароли и работает только в базе без проектов.

Откройте <http://127.0.0.1:8000>. На Windows можно запустить `start.bat`: он инициализирует базу при первом запуске и запускает сервер. Если команда `python` недоступна, установите Python и добавьте его в PATH либо используйте `py -3` вместо `python`.

Данные сохраняются в `data/hydroflow.db` между запусками. Пароли, рабочая база, вложения и исходный отчёт о практике в репозиторий не включены.

## PostgreSQL через Docker Compose

Нужны Docker Engine с Compose либо Docker Desktop.

1. Скопируйте `.env.example` в `.env`. Задайте `POSTGRES_PASSWORD`: случайную строку из букв и цифр длиной не менее 24 символов. `.env` не добавляется в Git.
2. Соберите контейнер и запустите базу:

   ```console
   docker compose build
   docker compose up -d db
   docker compose run --rm app python -m hydroflow init --email admin@example.local
   docker compose run --rm app python -m hydroflow demo
   docker compose up -d app
   ```

3. Откройте <http://localhost:8000>. База хранится в томе `pgdata`. Команда `docker compose down` сохраняет том; `down -v` удаляет данные.

Без Docker установите `pip install -r requirements.txt`, задайте `DATABASE_URL=postgresql://...` средствами своей оболочки и выполните `python -m hydroflow init`. Не храните строку подключения в исходном коде.

## Проверки

```console
python -m unittest discover -s tests -v
node --check static/app.js
```

В наборе 57 тестов (44 прежних и 13 новых): аутентификация, CSRF, блокировка, изоляция проектов, матрица ролей, согласование, конкурентные версии и связи, назначения, валидация запросов, вложения, отчёты, откат транзакций, SQL-инъекции, CSV, CLI и восстановление резервной копии.

Для PostgreSQL задайте `TEST_DATABASE_URL` на **отдельную тестовую базу**. Каждый тест создаёт случайную схему `hydroflow_test_*` и удаляет только её при завершении; нужны права CREATE SCHEMA. Очистка существующих таблиц устранена. SQLite всегда использует временные файлы. Никогда не указывайте рабочую базу.

Браузерный сценарий:

```console
npm install --no-save playwright@1.62.1
npx playwright install chromium
```

Запустите сервер на отдельной тестовой базе, задайте `HF_TEST_PASSWORD` и при необходимости `HF_TEST_EMAIL` и `HF_TEST_URL`, затем выполните `node tests/browser_smoke.cjs` и `node tests/browser_audit.cjs`. Второй сценарий требует администратора и создаёт синтетические учётные записи для всех ролей. Для установленного Chrome можно задать `HF_BROWSER_CHANNEL=chrome`. В CI предусмотрены SQLite, PostgreSQL, Chromium и Docker Compose.

После аудита 27 октября в [GitHub Actions #5](https://github.com/mln2k/hydroflow/actions/runs/40499708234) успешно завершились все шесть заданий: 44 теста на SQLite с Python 3.11–3.13, PostgreSQL 16, два браузерных сценария Chromium и Docker Compose. Подробности, исторические результаты и ограничения описаны в [docs/testing.md](docs/testing.md).

Для полностью отдельной учебной установки (пути должны быть новыми):

```powershell
.\.venv\Scripts\python.exe scripts/create_demo.py --database demo-local/hydroflow.db --accounts demo-local/DEMO-ACCESS.txt
$env:DATABASE_URL = "sqlite:///demo-local/hydroflow.db"
.\.venv\Scripts\python.exe -m hydroflow serve
```

Генератор создаёт шесть ролей, проект, требования, задачи, этап и документ. Случайные учебные пароли находятся только в отдельной памятке; не используйте их в реальной установке. `demo-local/` исключён из Git. На macOS используйте `python` из активированного venv и `export DATABASE_URL=sqlite:///demo-local/hydroflow.db`. Не запускайте demo в рабочей БД.

`/account` позволяет изменить имя и пароль; email доступен только для чтения. `/feedback` хранит собственные обращения; `/admin/feedback` и `/admin/users` доступны только ADMIN. Роль PM внутри проекта не предоставляет системное администрирование.

При обновлении сделайте копию БД, установите новые зависимости и выполните `python -m hydroflow init`. Миграция v2 добавляет обращения и строку блокировки администраторов, сохраняя прежние данные. Подробности — в operations.md и data-model.md.

Для свободного хостинга подготовлены `render.yaml` и `python -m hydroflow.deploy` с PostgreSQL Neon. Публичный URL пока отсутствует: владельцу нужно подключить аккаунты и задать секреты по deployment.md. Яндекс.Браузер, физические устройства, авторство студента/50 коммитов и 2000 логических строк не подтверждены. Полное соответствие требованиям не заявляется.
